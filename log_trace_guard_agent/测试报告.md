## 一、项目概述

### 1.1 项目简介

**日志溯源卫士智能体（Log Trace Guard Agent）** 是一个 AI 驱动的日志分析与安全实训平台，采用模块化七层架构，集成日志解析、日志采集、脚本生成、合规审计、安全威胁狩猎、规划咨询和攻防实训七大核心功能模块。

### 1.2 技术栈

| 组件     | 技术选型                                        |
| -------- | ----------------------------------------------- |
| 后端框架 | FastAPI (Python 3.10)                           |
| 向量库   | ChromaDB 1.4.1                                  |
| 嵌入模型 | N-gram 降级嵌入（BGE 需 tf-keras，已预检跳过）  |
| LLM 对接 | DeepSeek V4 Flash（OpenAI 兼容接口）            |
| 规则引擎 | 正则 + 风险基线 双引擎                          |
| 前端     | Vue 3 + Element Plus + Vite                     |
| 数据存储 | 外部 JSON 配置 + ChromaDB 向量库 + 内存 Session |

### 1.3 七层分层架构

```
┌──────────────────────────────────────────────────┐
│  app/          — FastAPI入口、路由挂载、全局异常   │
│  modules/      — 七大业务模块（零耦合）            │
│    ├── log_parse     日志解析                     │
│    ├── log_collect   日志采集                     │
│    ├── script_gen    脚本生成                     │
│    ├── compliance    合规审计                     │
│    ├── log_correlate 安全威胁狩猎（v3.0 新增）    │
│    ├── advisory      规划咨询（v3.1 新增）        │
│    └── training      攻防实训                     │
│  core/         — AI工厂、规则引擎、RAG知识库、   │
│                 上下文管理器                      │
│  common/       — 日志、文件、JSON、返回封装工具    │
│  data/         — 向量库、规则库、案例库           │
└──────────────────────────────────────────────────┘
```

### 1.4 三层通用架构（规则引擎 + RAG + LLM）

```
用户请求
  │
  ▼
┌──────────────┐    匹配成功     ┌──────────────┐
│  规则引擎     │ ──────────────▶ │  直接返回     │
│  (JSON/正则)  │                └──────────────┘
└──────┬───────┘
       │ 匹配不足
       ▼
┌──────────────┐    检索到知识    ┌──────────────┐
│  RAG 知识库   │ ──────────────▶ │  补充返回     │
│  (ChromaDB)  │                └──────────────┘
└──────┬───────┘
       │ 无知识 / 需深度解读
       ▼
┌──────────────┐    生成回答      ┌──────────────┐
│  LLM 推理     │ ──────────────▶ │  智能返回     │
│  (DeepSeek)  │                └──────────────┘
```

### 1.5 核心设计规范

- **工厂注册模式**: 所有策略通过 `register()` 外部注册，禁止硬编码实例化
- **配置外置**: 所有映射表、阈值、推荐文本存放 `data/rule_data/` JSON 文件
- **Pydantic 校验**: 所有 API 入参通过 Pydantic 模型强类型校验
- **兜底设计**: 未知场景统一返回兜底方案 + 人工复核提示
- **模块零耦合**: 业务模块禁止互相 import，跨模块数据走 ContextManager
- **绝对路径**: settings.py 基于项目根目录计算绝对路径，不受 CWD 影响

## 七、已知限制

1. **BGE 嵌入模型不可用** — 当前环境 Keras 3 与 transformers 不兼容，需安装 `tf-keras` 才能使用语义嵌入，当前使用 N-gram 降级
2. **LLM API 配额** — DeepSeek API 偶尔返回 402（欠费），LLM 层自动降级到规则/RAG 兜底
3. **嵌入质量** — N-gram 嵌入为非语义向量，检索精度低于 BGE 语义嵌入
4. **Splunk 连通性测试依赖外部服务** — CLI 中该测试标记为 skip，需 Splunk 实例在线（联调可用 `scripts/dev/mock_services.py`）
5. **log_correlate 大文件分析性能** — 单文件超 100MB 时 FileCrunch 耗时 >30s，建议分片处理
6. **「保存到 .env」依赖文件写权限** — Docker 部署容器内重启丢失，生产环境应通过环境变量注入
