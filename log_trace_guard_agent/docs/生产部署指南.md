# 生产部署指南

> 适用版本：v3.0+
> 更新时间：2026-07-28

---

## 一、架构概述

```
                       ┌──────────────────────┐
                       │      Nginx (可选)     │  端口 80/443
                       │  反向代理 + SSL 终结  │
                       └──────────┬───────────┘
                                  │
                       ┌──────────▼───────────┐
                       │   Uvicorn (Python)    │  端口 8000
                       │   FastAPI 应用        │
                       │                       │
                       │   ┌─────────────────┐ │
                       │   │  frontend/dist/  │ │  Vite 构建产物
                       │   │  (静态文件)       │ │  由 FastAPI 挂载
                       │   └─────────────────┘ │
                       └───────────────────────┘
```

**特点**：前端 Vite 构建产物（`frontend/dist/`）由后端 FastAPI 直接挂载为静态文件，**单端口部署**，不需要额外的前端服务器。

## 二、环境变量配置（生产环境）

### 2.1 核心原则

生产环境**不建议使用 `.env` 文件**，改用系统环境变量或 Docker 环境变量。原因：

| 方式 | 本地开发 | 生产环境 |
|------|:-------:|:--------:|
| `.env` 文件 | ✅ 方便 | ❌ 文件权限、多实例不同步 |
| 系统环境变量 | 手动 export 麻烦 | ✅ systemd/Docker/K8s 原生支持 |

### 2.2 必需变量

```bash
# LLM API（必填）
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=https://raytoken.com.cn/v1
LLM_MODEL_NAME=deepseek-v4-flash

# 服务端口（可选，默认 8000）
SERVICE_PORT=8000
```

### 2.3 可选变量（Splunk / ES）

生产环境有两种配置方式，**推荐方式 A**：

#### 方式 A（推荐）：环境变量全局配置

```bash
# Splunk
SPLUNK_BASE_URL=https://splunk.company.com:8089
SPLUNK_AUTH_TOKEN=your_token
SPLUNK_VERIFY_SSL=true

# ES
ES_BASE_URL=http://elasticsearch:9200
ES_USERNAME=elastic
ES_PASSWORD=your_password
ES_VERIFY_SSL=false
```

> ✅ 全局生效，重启即更新，适合有独立 ES/Splunk 集群的组织

#### 方式 B（备选）：前端 localStorage

用户在浏览器系统设置中填写 Splunk/ES 配置，保存在 `localStorage`，每次 API 请求携带到后端。

> ✅ 无需服务端配置，适合多用户各自连接不同集群
> ❌ 更换浏览器/清除缓存需重新配置

## 三、部署方案

### 方案 1：Docker 部署（推荐）

创建 Dockerfile（项目根目录）：

```dockerfile
# ── 构建阶段：编译前端 ──
FROM node:20-alpine AS frontend-builder
WORKDIR /app/frontend
COPY frontend/package*.json ./
RUN npm install
COPY frontend/ .
RUN npm run build

# ── 运行阶段 ──
FROM python:3.11-slim
WORKDIR /app

# 系统依赖
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl && \
    rm -rf /var/lib/apt/lists/*

# Python 依赖
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 项目代码
COPY app/ app/
COPY common/ common/
COPY core/ core/
COPY modules/ modules/
COPY data/ data/

# 前端构建产物
COPY --from=frontend-builder /app/frontend/dist frontend/dist/

# 端口
EXPOSE 8000

# 健康检查
HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
  CMD curl -f http://localhost:8000/health || exit 1

# 启动
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

创建 `docker-compose.yml`：

```yaml
version: '3.8'

services:
  log-guard:
    build: .
    container_name: log-trace-guard
    ports:
      - "8000:8000"
    environment:
      # LLM（必填）
      - LLM_API_KEY=${LLM_API_KEY}
      - LLM_BASE_URL=https://raytoken.com.cn/v1
      - LLM_MODEL_NAME=deepseek-v4-flash
      # Splunk（可选）
      - SPLUNK_BASE_URL=${SPLUNK_BASE_URL:-}
      - SPLUNK_AUTH_TOKEN=${SPLUNK_AUTH_TOKEN:-}
      # ES（可选）
      - ES_BASE_URL=${ES_BASE_URL:-}
      - ES_USERNAME=${ES_USERNAME:-}
      - ES_PASSWORD=${ES_PASSWORD:-}
    volumes:
      # 持久化 ChromaDB 向量库
      - chroma-data:/app/data/chroma_db
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 5s
      retries: 3

volumes:
  chroma-data:
```

使用 `.env` 文件（仅 Docker Compose 读取，不传入容器）：

```bash
# .env (与 docker-compose.yml 同目录)
LLM_API_KEY=webray-key-xxx
SPLUNK_BASE_URL=https://splunk.company.com:8089
SPLUNK_AUTH_TOKEN=xxx
ES_BASE_URL=http://es-cluster:9200
```

启动：

```bash
docker compose up -d
```

### 方案 2：systemd 服务部署（裸机/VM）

构建前端：

```bash
cd frontend
npm install
npm run build
```

创建 systemd 服务 `/etc/systemd/system/log-guard.service`：

```ini
[Unit]
Description=日志溯源卫士智能体
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/log-trace-guard
Environment=LLM_API_KEY=webray-key-xxx
Environment=LLM_BASE_URL=https://raytoken.com.cn/v1
Environment=LLM_MODEL_NAME=deepseek-v4-flash
Environment=ES_BASE_URL=http://localhost:9200
Environment=SPLUNK_BASE_URL=https://splunk.company.com:8089
ExecStart=/usr/local/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable log-guard
sudo systemctl start log-guard
sudo systemctl status log-guard
```

### 方案 3：Nginx 反代 + SSL（可选）

如果需要在 80/443 端口提供服务或加 SSL，在前面加一层 Nginx：

```nginx
server {
    listen 80;
    server_name log-guard.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name log-guard.example.com;

    ssl_certificate     /etc/ssl/certs/log-guard.crt;
    ssl_certificate_key /etc/ssl/private/log-guard.key;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持（用于 SSE 流式分析）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # 限制上传大小（匹配后端 MAX_UPLOAD_SIZE_MB）
    client_max_body_size 10m;
}
```

## 四、ES / Splunk 配置在部署中的处理

### 4.1 三种配置途径的优先级

1. **前端 localStorage**（每次请求体携带，优先级最高）
2. **系统环境变量**（`ES_BASE_URL` / `SPLUNK_BASE_URL` 等）
3. ~~`.env` 文件~~ （生产环境不使用）

### 4.2 「保存到 .env」按钮在部署环境的行为

前端面板的 **保存到 .env** 按钮调用 `POST /api/v1/script-gen/es/config`，会尝试写入服务器上的 `.env` 文件。

| 部署方式 | 是否可用 | 说明 |
|----------|:--------:|------|
| 本地开发 `python run` | ✅ 可用 | 文件可写，重启后端后生效 |
| Docker 部署 | ❌ 不可用 | 容器内文件系统重启后丢失 |
| systemd 部署 | ⚠️ 取决于权限 | 需要 `www-data` 用户对项目目录有写权限 |

**生产环境建议**：
- Docker 部署：通过 `docker-compose.yml` 的 `environment` 或 Docker 的 `-e` 参数设置
- systemd 部署：通过 `Environment=` 配置
- K8s 部署：通过 ConfigMap + Secret

### 4.3 多用户场景

如果多个用户需要连接**不同的 ES/Splunk 集群**：

- 使用前端 **临时保存**（localStorage），每个用户独立配置
- 后端不需要配置任何 ES/Splunk 环境变量
- ES/Splunk 配置信息仅存于用户浏览器，不会互相干扰
- 适合 SOC 团队中不同分析师跟踪不同数据源的场景

## 五、生产 Checklist

- [ ] LLM_API_KEY 已配置（使用真实 Key，非占位符）
- [ ] 前端已构建（`cd frontend && npm install && npm run build`）
- [ ] `.env` 文件已移除或权限收紧（`chmod 600 .env`）
- [ ] 向量库目录已挂载持久卷（ChromaDB）

- [ ] 上传大小限制已配置（nginx `client_max_body_size`）
- [ ] 日志轮转已配置（`data/chroma_db` 和 `data/upload_temp`）

## 六、常见问题

### Q1: 部署后前端白屏 / 404

确认 `frontend/dist/index.html` 存在。如果没有，执行：

```bash
cd frontend && npm install && npm run build
```

### Q2: 环境变量修改后不生效

- **Docker**：需要重新创建容器（`docker compose down && docker compose up -d`）
- **systemd**：需要重启服务（`sudo systemctl restart log-guard`）
- **后端读取时机**：启动时一次性加载，运行时修改不会热生效

### Q3: 部署后 ES "保存到 .env" 报错

这是正常现象。生产环境请通过**系统环境变量**或 **Docker environment** 配置 ES，不要依赖运行时写入 `.env`。

### Q4: 如何确认服务正常运行？

```bash
curl http://localhost:8000/health
# 应返回: {"code":200,"data":{"status":"healthy"},"msg":"success"}
```

### Q5: 需要修改后端端口？

```bash
# Docker：修改 docker-compose.yml 的 ports + environment
# systemd：修改 ExecStart 中的 --port 参数
# 默认：8000
```
