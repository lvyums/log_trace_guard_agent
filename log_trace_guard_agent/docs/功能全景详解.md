## 零、总体架构：三层渐进式 + 双形态交付

### 0.1 三层渐进式架构（核心设计哲学）

```
第一层 正则/规则引擎   → 确定性匹配, ~5ms, 覆盖 70% 常规场景, 零 API 成本
第二层 RAG 知识库       → 知识兜底, 259→254 条文档向量检索, 处理"查得到"的场景
第三层 LLM 语义分析     → 只在灰区出手, temperature=0.1, 处理"猜和编"的场景
```

设计原则一句话：**"能确定的事就不猜，能查到的事就不编，猜和编的事才交给 AI。"**

- 每一层都有明确的触发条件与降级路径，任何一层失败都不会让功能整体崩溃
- 三层共享同一套数据（rule_data JSON），LLM 层从不重复造轮子
- 用 `method` 字段标记实际命中的引擎（keyword / llm / hybrid），前端据此展示不同标签

### 0.2 双形态交付（Web + CLI）

| 维度 | Web 端（FastAPI + Vue3） | CLI 端（log-guard 命令） |
|------|------------------------|------------------------|
| 定位 | 可视化、报告、实训、非 CLI 用户 | CI/CD、SSH 服务器、批量处理、cron |
| 架构 | 异步 async + ContextManager 依赖注入 | 同步 requests + ConversationContext |
| LLM | LLMFactory 异步 chat | LLMClient 同步 chat |
| RAG | ChromaDB 向量库 | JSON + API embedding（无本地向量库） |
| 数据 | API 传 file_content | LogReader 本地文件访问 |

两套代码共享同一份规则 JSON 与版本线（当前 3.2.0），CLI 是 Web 端的轻量派生版。

### 0.3 六大设计模式（贯穿全项目）

1. **工厂模式** — 解析器/采集策略/评分策略全部 `StrategyFactory.register()` 注册，新增策略不改调用方
2. **策略模式** — 6 个日志解析器、4 个采集策略、4 个评分策略各自实现统一接口
3. **模板方法** — 解析器共享验证流程（base_parser.py），子类只实现特征提取
4. **上下文模式** — ContextManager 贯穿请求，跨模块数据走 core/context_manager.py
5. **两段式管道** — 快路径（关键词，零成本）→ 慢路径（LLM，一次调用）
6. **单例** — 缓存/日志/知识库分片均为单例，避免重复加载

## 一、日志解析模块（9 端点）

### 1.1 实现机制

**解析器注册表（工厂 + 策略 + 模板方法三合一）**：

```
base_parser.py     # 抽象基类：统一 validate/parse/extract 流程（模板方法）
parser_factory.py  # ParserFactory：按日志类型注册/分派解析器（工厂）
ssh_parse.py       # SSHParser
web_parse.py       # WebParser
waf_parse.py       # WAFParser
firewall_parse.py  # FirewallParser
db_parse.py        # DBParser
traffic_parse.py   # TrafficParser（必须最先注册，否则 CSV+IP 行被误判为 web）
```

**识别流程（5 步）**：
```
原始日志行 → _preprocess 清洗 → 类型识别（关键词打分）→ 解析器分派 → 结构化字段
                                              ↓ 未命中
                                        LLM 兜底识别（_llm_identify_fallback）
```

- **类型识别**：内置 5 类解析器的识别关键词表（sshd/HTTP/WAF/drop/mysql），
  正则提取特征后按命中数打分，得分最高者胜出
- **结构化提取**：各解析器用专属正则 pattern 提取 18+ 标准字段
  （timestamp / src_ip / dst_ip / user / action / status / risk_level / confidence 等）
- **风险研判**：`assess_risk()` 结合字段特征输出 P0-P3 风险等级 + 置信度 + 修复建议
- **LLM 兜底**：关键词全不命中时，`_llm_parse_fallback()` 让 LLM 做格式识别，
  返回带 `_extract_json` 容错解析的结构化结果 —— 这是"三层架构"在单模块内的体现

### 1.2 特色亮点

- **5+1 解析器覆盖**：SSH（6 个正则 pattern 检测高危命令）、Web（3 种格式）、
  WAF（11 种攻击类型中英映射）、防火墙（4 种格式）、DB（15 种危险 SQL 关键词）、
  流量（通用 CSV/IP 行）
- **批量 + 文件双通道**：`/parse/batch` 批量解析、`/parse/batch-file` 文件解析、
  `/explain/batch` 批量字段释义，全部异步并发处理
- **字段释义**：`/explain` 不只给字段名，还解释字段含义与安全意义，面向初学者友好
- **结果可联动**：解析结果可直接送"日志联合审查"（跨模块闭环）

## 二、日志采集架构指导模块（5 端点）

### 2.1 实现机制

**4 种采集策略（策略模式 + 工厂注册）**：

| 策略 | 支持设备 | 协议 |
|------|---------|------|
| SyslogCollectStrategy | 防火墙/WAF/IDS/IPS/路由/交换 | syslog UDP/TCP 514 |
| FileCollectStrategy | 服务器/Web/Nginx/Apache | file（Filebeat） |
| DBSyncCollectStrategy | MySQL/PostgreSQL/SQLServer/Oracle | db_sync |
| AgentCollectStrategy | 堡垒机/HIDS/EDR/SIEM | agent 转发 |

**设备匹配三级评分**（`match_device`）：
```
精确型号匹配 → 95 分
类型匹配     → 80 分
模糊子串     → 50 分
```

**故障诊断算法**（`diagnose_fault`，5 维度总分 100）：
```
5 个维度（连接性/认证/格式/权限/资源）各占 20 分，
按 fault_type 从 fault_kb.json（9 类故障知识）查模板，
关键匹配 + RAG 补充 + LLM 深挖（关键词得分 < 30 时升级到 LLM）
```

### 2.2 特色亮点

- **采集方案生成**：`generate_plan()` 输出设备 → 策略 → 协议 → 配置模板 → 注意事项完整链条，
  `include_config` 参数可附带可落地的配置文件
- **批量规划**：`/plan/batch` 一次传入多设备清单，批量产出采集方案
- **知识库增强**：`_get_rag_supplements()` 从 collection 知识库（5 条）检索补充信息，
  方案输出不限于硬编码模板
- **故障知识库**：fault_kb.json 内置 9 类典型故障
  （ssh_connect_failure / network_timeout / ssh_auth_failure / port_unreachable /
   log_lost / format_error / time_offset / transport_interrupt / storage_failure）

## 三、脚本生成与技术赋能模块（13 端点，全项目最大模块）

### 3.1 实现机制

**四大生成引擎 + 双平台执行 + 优化器**：

```
generate_regex    正则生成：4 级级联（场景识别→模板匹配→RAG 兜底→通用兜底）
generate_es_query ES 查询：场景关键词评分→模板查找→时间过滤器构建→RAG 兜底
trace_attack      攻击溯源：6 级阶段 + 7 步流水线 + 3 种搜索脚本
optimize_script   脚本优化：正则编译检查 / ES JSON 有效性校验
```

**攻击溯源 6 级阶段**：
```
侦查探测 → 初始入侵 → 权限提升 → 横向移动 → 持久化驻留 → 数据窃取/破坏
```

**溯源 7 步流水线**（`trace_attack` + TraceLinkStrategy）：
```
1. 接收日志与攻击类型
2. 逐行事件分析（_analyze_log_event，支持 pre_analyzed 预分析加速）
3. 时间轴构建（TimelineAnalyzer）
4. 攻击阶段标注（按风险等级/事件类型映射 Kill Chain 阶段）
5. 3 种搜索脚本生成（grep / ES DSL / Splunk SPL）
6. 关键证据聚合（IP、账户、特征关键词）
7. 输出溯源报告（Markdown/JSON 双格式）
```

**双平台执行链路**：
```
Splunk:  common/splunk_client.py → POST /services/search/jobs → 轮询 → GET results
ES:      common/es_client.py     → POST /{index}/_search（标准 REST，兼容 v7/v8）
两者都支持 Basic Auth + Bearer Token，连接配置三级持久化（.env / 前端面板 / CLI config.json）
```

**脚本优化器**：`_analyze_regex()` 检查正则是否可编译、ES JSON 是否合法、
query 字段是否存在，输出优化建议 + 修正后脚本。

### 3.2 特色亮点

- **生成 → 执行 → 闭环**：不止生成脚本，还能一键连接真实 Splunk/ES 执行并返回结果
  （命中数/耗时/样本数据），这是 v3.1 起最大的能力升级
- **Splunk SPL 5 场景模板**：SSH爆破 / SQL注入 / Web攻击 / 异常流量 / 数据泄露，
  中文场景名智能匹配（scene_label + 关键字组合打分）
- **连接配置双端持久化**：Web 端前端面板（localStorage 临时 + .env 永久双保存策略）、
  CLI 端 config.json；企业多分析师共享场景下换设备不丢配置（用户明确要求的设计）
- **pre_analyzed 预分析**：溯源时传入关联分析已检出的 matched_keywords/indicators/
  matched_line_indices，跳过重复解析直接精准生成脚本（跨模块闭环 P1 项）

## 四、合规审计基线模块（4 端点）

### 4.1 实现机制

**合规标准库**（compliance_standards.json + compliance_baselines.json）：
```
等保 2.0（8 项要求）
网络安全法（2 项要求）
数据安全法（2 项要求）
```

**RAG 精准问答**（`compliance_qa`）：
```
问题 → compliance 知识库检索（10 条）→ RAG 上下文 → LLM 解读
asset_type 参数可限定场景（服务器/数据库/网络设备/应用系统）
```

**个性化基线生成**（`generate_baseline`）：
```
6 大监控场景 × 资产规模自适应：
  <30 台   → 宽松基线
  30-500 台 → 标准基线
  >500 台  → 严格基线
```

**8 项硬编码检查 + 评分算法**：
```
检查项：日志留存天数/覆盖范围/备份策略/访问控制/加密/告警/审计/应急
评分：max(0, 100 - (critical×30 + high×15 + medium×8 + low×3))
```

### 4.2 特色亮点

- **批量并行**：`/check/batch` 一次传入多个检查对象并行执行，汇总结果报告
- **业务类型定制**：baseline 支持 business_type 参数（enterprise/government/finance 等），

- **问答可溯源**：RAG 检索结果带回知识来源，LLM 回答基于知识库不编造（prompt 显式要求）

## 五、攻防实训考核模块（4 端点）

### 5.1 实现机制

**双模式场景下发**（`dispatch_tasks`）：

```
模式 1 动态生成（v3.1+）：
  Analyze.vue 检出攻击链 → chain_data → TemporalAnalyzer.generate_training()
    → LLM 实时生成 4 任务（类型识别/阶段分析/证据提取/处置建议）
    → TaskEngine.inject_scenario() 注入为 DYN_<timestamp>_<n>
    → 前端弹窗展示场景信息 → "立即进入实训" 跳转提交页

模式 2 传统预置（v2 保留）：
  scenario_id/category → training_scenarios.json（12 场景 / 25 任务）直接下发
```

**标准答案两种结构**（2026-08-06 评分链路修复的核心）：
```
LLM/fallback 生成 → 简版 {attack_type, risk_level, key_indicators, ...}
check_strategy 期望 → 完整版 {key_fields: {...}, scoring_rules: {...}, correct_answer: {...}}
中间必须经 _adapt_dynamic_standard_answers() 适配转换
```

**双维度校验**（`submit_answer` → CheckStrategyFactory）：
```
维度 1 规则精准匹配：key_fields 命中任一关键词即字段正确（hits > 0）
维度 2 语义相似度：未命中时 SequenceMatcher ≥ 0.70 给 partial（0.5 分）
4 种评分策略：ConclusionCheckStrategy（步骤1-3）/ RuleCheckStrategy /
             ScriptCheckStrategy / PlanCheckStrategy（步骤4）
```

**评分阈值**：A ≥90 直接通过 · B 70-89 提示优化 · C <70 判错并强制复盘

**讲解与报告**：
```
ErrorAnalysis    → LLM 生成知识点讲解（降级用 fault_kb 硬编码知识库）
report_gen       → 全程记录 + 6 类薄弱项分析 + 标准化报告（Markdown/JSON）
/analyze-stream  → 流式输出讲解过程
```

### 5.2 特色亮点

- **动态场景生成**：真实攻击链 → 实训场景，学员练的是"刚才分析出的那次攻击"，
  不是固定题目 —— 教学与实战闭环
- **标准答案逐字段对照**：Submit.vue 结果区展示 correct_answer 全字段
  （字段名 + 标准值 + 是否命中可视化），学员清楚知道"哪步对了哪步差在哪"
- **评分容错体系**：长句拆分（"权限提升/入侵"→拆出 3 个关键词）、同义词映射
  （提权↔权限提升、封禁↔封锁/拉黑/封IP、重置↔修改密码）、timeline 拆 HH:MM
  —— 学员措辞不同也能得分，避免"答对但 0 分"
- **LLM 静默失败根治**：max_tokens 512→2048（场景生成传 4096）、空 content 判定失败、
  reasoning_content 兜底 —— 场景生成从"0 字符静默 fallback"到"2482+ 字符完整 JSON"
- **降级场景也可评分**：_fallback_scenario() 从真实日志正则提取 IP/账户/时间/阶段/风险
  （过滤 sshd "invalid user" 提示词），LLM 挂了学员答对照样得分
- 端到端效果：同一份学员答案从修复前 186/400（步骤4 HTTP 500）→ 316/400（步骤4 100/A）

## 六、安全威胁狩猎模块（8 端点，日志联合审查升级）

### 6.1 实现机制

**16 种安全攻击链**（correlation_patterns.json rules 数组，v3.0 重构删除了 18 条运维规则）：
```
SSH爆破提权 / 暴力破解 / SQL注入 / Web扫描利用 / 入口入侵→横向移动 /
权限提升 / 数据窃取 / C2通信 / 勒索软件 / 内网侦察 / Web攻击→数据窃密 /
DNS隧道 / 供应链攻击 / 内部威胁 / WAF绕过→攻击成功 / 认证失败
```

**双引擎分析**（`correlate_logs`）：

```
Stage 1: 关键词预过滤（AttackChainMatcher）
  正则匹配所有规则的 keyword patterns
  score >= threshold → 直接返回（毫秒级，零 API 成本）
  ↓ 未命中
Stage 2: LLM 语义分析（LLMChainAnalyzer）
  一次性发送所有日志行（O(1) 调用，绝不逐行）
  LLM 返回结构化攻击链 JSON（宽松判断：≥2 阶段证据即报告）

use_llm=True 合并模式：关键词 + LLM 双跑，按 chain_name 去重取 max confidence
```

**4 层 JSON 容错**（`_parse_llm_json`）：
```
完整 JSON 直解 → 截断修复（补括号）→ 正则提取片段 → 关键词兜底
```

**时序推理增强**（TemporalAnalyzer，v3.2 后端）：
```
4 个维度：时间戳提取 / 攻击阶段推断（Kill Chain 映射）/
          IP 因果链（跨阶段同源 IP 连续性）/ 动态置信度
置信度公式：base + (0.12 序列有效) + ip_continuity×0.10 + time_gap_score
输出 temporal 字段：timeline / stages_observed / adjusted_confidence
```

### 6.2 特色亮点

- **跨模块双联动**（闭环核心）：
  - 攻击链 → `/to-trace` → 溯源脚本（grep/ES/SPL 三通道）
  - 攻击链 → `/to-scenario` → 动态实训场景（见模块五）
- **多文件上传**：`/file-crunch` 支持 file_paths 列表多文件同时分析，
  带来源标签合并（"# ── 来源: xxx ──"），上限 2000 行
- **前端时间轴可视化**：攻击链按 Kill Chain 阶段分组的纵向 CSS 时间轴，
  阶段标签只在切换时显示（减少视觉噪音）、风险等级色点 + 左边框高亮
- **method 标签**：关键词=绿/LLM=橙/混合=蓝，用户能看到每次分析用的什么引擎
- **溯源结果回流**：Splunk 搜索结果可一键送回关联分析重新研判（跨模块 store）

## 八、RAG 知识库体系（5 分片 · 254 条）

### 8.1 实现机制

**知识库分片管理**（RAGFactory + KnowledgeBase 单例）：

| 知识库 | 文档数 | 数据来源文件 |
|--------|-------|-------------|
| log_basics | 8 | log_features.json, risk_rules.json |
| compliance | 10 | compliance_standards.json, compliance_baselines.json |
| collection | 5 | collect_templates.json, device_protocol.json, arch_templates.json |
| scripts | 59 | 9 个 script_gen_*.json |
| cases | 172 | training_scenarios.json, fault_kb.json, correlation_patterns.json |

**导入管线**（kb_ingest.py）：
```
rule_data JSON → _flatten_json 展平（description/detail/requirement 等字段）
  → _chunk_text 按 500 字符切分 → ChromaDB 向量化（分片持久化）
启动时检查 store.count()，已有数据跳过（幂等）
```

**检索链路**（KnowledgeBase.retrieve → rerank）：
```
查询 → 向量检索 top_k=5 → 结果重排（rerank）→ RetrievalResult
三级嵌入降级：BGE (1024维) → MiniLM (384维) → N-gram (128维)
```

### 8.2 特色亮点

- **五大知识库按业务域隔离**：每个模块只检索自己的分片，检索精度高、互不干扰
- **三级嵌入降级**：无 GPU/无网络时自动降级到 N-gram，功能不中断
- **数据驱动**：所有知识来自 rule_data JSON，非硬编码 —— 加一条规则 = 加一条知识

## 九、CLI 工具（log-guard 命令，零第三方依赖）

### 9.1 实现机制

**双模式交互**：
```
模式 1 菜单模式：主菜单 8 项（选择日志文件 + 5 业务模块 + AI 对话 + 退出）
  script_gen 子菜单 6 项：正则 / ES 查询 / Splunk SPL / 溯源 / 优化 / 连接配置

**意图分类器**（intent_classifier.py）：
```
6 类意图：log_parse / collection / compliance / script_gen / correlation / general
INTENT_MODULES 映射表：意图 → 业务模块
confidence >= threshold 才调业务模块，否则走通用问答
```

**30 项命令行参数**（argparse）：

--splunk-test / --splunk-search / --es-test / --es-search（退出码 0/1/2）/
--json / --version / --log-file / --log-dir / --device-type / --asset-type ...
```

**零依赖设计**：唯一运行时依赖 requests>=2.25，SPL/ES 执行用 urllib.request + base64，
纯标准库实现 —— 任何服务器 pip install 即用。

### 9.2 特色亮点
